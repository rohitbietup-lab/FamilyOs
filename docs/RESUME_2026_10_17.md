# Resume verification, 17 October 2026

## Local startup

The existing Downloads/FamilyOS-Latest installation matched repository commit
`a5330ae`. Its launcher was untracked; no FamilyOS service, scheduled task or
Startup shortcut existed, and neither web server nor worker was running.
The database had an abandoned full-sync lease from 3 October.

The launcher is now versioned. It reloads saved per-user settings, fixes the
database path to this installation's instance directory, preserves the original
encryption key, checks port ownership (including Windows virtualenv delegation),
starts Waitress on 127.0.0.1 only, and checks readiness over IPv4. It starts the
Gmail worker and an existing local ClamAV installation when available. Headless
failures go to instance/launcher-error.log rather than an invisible dialog.

From the installed checkout, run `scripts/Install-Startup.ps1` in PowerShell.
This installs a current-user Startup shortcut to `scripts/Watch-FamilyOS.ps1`.
The supervisor checks every 30 seconds, restarts missing processes, and uses a
mutex to avoid duplicate supervisors. Use `scripts/Start-FamilyOS.ps1` for manual
launch; `-NoBrowser` is suitable for headless checks, `-NoWorker` for web-only
diagnosis. It is local development mode, intended only for this Windows account.
No service or boot-before-login configuration is installed. Removing the Startup
shortcut disables future automatic startup; terminate the supervisor before
stopping child processes for maintenance. The scanner uses the installed
ClamAV configuration; keep it loopback-only and update its signatures separately.

## Gmail and storage

OAuth settings and the private paired Web client file are present. A real refresh
request returned Google `invalid_grant`; reconnect Gmail in the Vault using the
same browser and Google consent. No credentials were printed or changed. The
worker recovered the expired lease and safely changed status to error, preserving
the checkpoint and all documents. Live attachment ingestion is blocked by that
authorization failure.

All 53 stored documents (51 Gmail, 2 manual) passed encrypted metadata decryption
and object length/SHA-256 checks. No new real documents were imported. Instance
ACLs were restricted to the current user, SYSTEM and Administrators; Vault root
already had those restrictions. Tokens, page checkpoints, document metadata and
objects are encrypted. The Vault key and application settings remain in the
user's Windows environment; OS account protection is required. SQLite metadata
and logs are not application-encrypted, as documented in OPERATIONS.md.

ClamAV was restarted and answered PING on loopback. Signature files are older
than seven days. Freshclam could not update Program Files/ClamAV/database because
the current process cannot write there. An administrator must update the installed
signatures (or provision a writable scanner installation). Scanner bypasses were
not introduced.

Import now requires a supported PDF/PNG/JPEG filename that itself matches a
document category. Subject keywords alone no longer qualify logos, banners or
generic attachments. Underscores are normalized for classification. Spam, trash
and draft messages are excluded even during incremental history processing.
Ambiguous filenames require manual upload; keyword matching cannot prove that a
document belongs to the family. Existing imports were preserved, not reclassified
or deleted. Full sync still enumerates attachment-bearing messages, while only
matching attachments are downloaded and stored; message bodies are not stored.

Synthetic tests cover OAuth state/PKCE/expiry/replay/scope, refresh requests and
five-minute throttling, attachment download, encrypted storage/download integrity,
hash deduplication including archived items, pagination/checkpoints, expired
history recovery, disconnect fencing, malware rejection, unrelated attachments,
incremental excluded labels and underscore filenames. The browser queues refresh
on Vault use; a running worker is necessary to process it.

Validation: 88 Django tests pass; migration drift check passes; separate-process
persistence and encrypted Vault backup/restore checks pass. Local login HTTP and
scanner PING were exercised. Actual Windows sign-out/reboot and renewed Google
consent require the user; neither is claimed as tested.
